# 访问控制与系统管理设计

## 1. 用户角色与权限矩阵

| 模块/操作                     | 管理员 | 业务员 | 财务 | 仓储 |
|------------------------------|--------|--------|------|------|

### 角色说明
- **管理员**：负责系统配置、用户与角色管理、全局监控与审计策略设定。
- **业务员**：负责客户关系维护、销售订单创建与跟进，可查看必要的库存与财务状态信息。
- **财务**：负责应收应付、账务核销、财务报表，拥有相关数据的增删改查权限。
- **仓储**：负责入库、出库、盘点、调拨等仓储执行操作，可读取订单与库存相关信息。

可以根据实际需要在上述角色上附加基于属性（ABAC）的细分策略，例如限定业务员只可访问所属客户或区域的数据。

## 2. 认证与授权机制

### 认证体系
1. **登录方式**
   - 支持用户名/密码、短信验证码、企业邮箱单点登录（SSO）。
   - 登录表单走 HTTPS 通道，采用滑块/图形验证码防暴力破解。
2. **Token 策略**
   - 后端签发短期访问令牌（JWT）+ 长期刷新令牌（Refresh Token）。
   - Access Token 设置 15 分钟有效期，Refresh Token 7 天有效期，可配置黑名单或撤销列表。
   - Token 中只包含必要的最小权限声明（角色、组织、关键属性），敏感信息使用 JWE 或通过用户信息接口按需查询。
3. **单点登录 (SSO)**
   - 支持与企业身份提供商（如 OAuth2/OIDC、SAML）对接。
   - SSO 登录成功后，通过身份提供商返回的断言换取本系统 Token。
   - 保留本地账号体系用于紧急运维或身份提供商故障时的兜底。
4. **多因素认证 (MFA)**
   - 对管理员、财务等高敏角色强制启用 MFA（TOTP/短信/硬件令牌）。

### 授权体系
1. **角色权限控制 (RBAC)**
   - 角色与权限资源（API、菜单、按钮、字段）通过多对多关系维护。
   - 角色可配置数据范围（全部、本部门、本人、自定义组织）。
2. **基于属性的扩展 (ABAC)**
   - 结合业务属性（订单所属区域、客户类型、仓库）细化访问控制。
   - 策略引擎在网关或服务层执行，支持组合规则（AND/OR/NOT）。
3. **权限缓存与动态刷新**
   - 用户登录后将角色与权限列表缓存至 Redis，设置合理 TTL。
   - 当角色或权限变更时，通过消息队列或事件通知触发缓存失效。
4. **接口保护**
   - API 网关或后端服务在请求入口校验 Token、角色和权限。
   - 对关键操作（如删除、审批）增加二次确认与操作口令。

## 3. 系统管理模块设计

### 3.1 角色管理界面
- 角色列表：展示角色名称、描述、启用状态、数据范围、最后更新时间。
- 角色编辑：支持配置菜单权限、按钮权限、数据范围、MFA 要求。
- 角色克隆：允许快速复制已有角色模板。
- 变更记录：在保存角色配置时自动记录变更内容与操作者。

### 3.2 权限分配界面
- 用户维度：
  - 用户列表内可快速查看所属角色、部门、最近登录时间。
  - 支持为用户直接授予临时权限或临时角色（带有效期）。
- 角色维度：
  - 通过树状结构展示菜单 → 功能点 → 接口/字段。
  - 支持批量勾选、搜索、按模块导出权限配置。
- 数据权限：
  - 为角色配置组织架构、仓库、业务线等数据范围。
  - 支持条件表达式（如「只允许查看华东仓库库存」）。

### 3.3 审计日志界面
- **日志采集**：
  - 记录登录、权限变更、关键操作（审批、删除、导出）。
  - 日志内容包含时间、操作者、角色、来源 IP、操作对象、结果、追踪 ID。
- **查询展示**：
  - 支持按时间、用户、模块、关键字过滤。
  - 提供详细视图，展示请求参数与变更前后数据差异。
- **导出与留存**：
  - 支持导出为 CSV/PDF，提供签名或水印防篡改。
  - 日志留存周期可配置（默认 12 个月），自动归档至冷存储。
- **告警与审计**：
  - 对异常操作（多次失败登录、越权访问）触发告警通知。
  - 审计员可在线标记与备注异常事件，形成闭环追踪。

## 4. 安全与合规要点
- 密码采用 PBKDF2/bcrypt/Argon2 等安全算法加盐存储。
- 登录失败次数限制与账户锁定策略，支持自助解锁或管理员解锁。
- 所有 Token 操作、权限修改需写入审计日志并支持追溯。
- 针对 API 访问设置速率限制与 IP 黑白名单，防止暴力请求。
- 定期对权限矩阵进行评估，结合岗位变动进行自动化回收。

## 5. 部署与集成建议
- 采用微服务或分层架构时，将认证服务独立部署，提供统一的 OAuth2/OIDC 接口。
- 前端通过集中路由守卫与按钮指令控制可见性；后端仍进行二次校验。
- 与企业微信、钉钉等 IM 系统对接，实现消息推送与审批流的闭环。
- 提供开放 API 时，对第三方应用采用 Client Credentials 流程并细分访问范围。

此设计可作为企业内部 CRM/OMS/WMS 系统的访问控制蓝图，后续可依据实际业务与合规要求进行定制化调整。
